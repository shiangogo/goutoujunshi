# 自動化與代理邊界

## 代理說明

| 項目 | 當前實現 |
| --- | --- |
| 觸發 | 使用者顯式調用，或宿主根據 AGY Skill frontmatter 描述匹配相關請求 |
| 所有者 | 使用者控制當前任務；倉庫維護者維護公開指令 |
| 自動運行 | 只在 AGY 對話任務內響應，不存在後臺或定時運行 |
| 可讀輸入 | 當前對話、按需Markdown、已同意的精簡記憶，以及使用者要求時的ChatLab安全查詢結果 |
| 必需工具 | 無；本地記憶與ChatLab均可選，失敗時降級到當前任務 |
| 外部副作用 | 現實訊息無；首次同意後可更新本地記憶，使用者明確要求匯入時可寫入ChatLab本地庫 |
| 審批 | 現實發送、刪除、聯繫或求助動作均由使用者自行決定 |

## 提示詞引導與硬邊界

`SKILL.md`包含首次建檔、情緒支持、知識路由、建議格式和安全邊界。這些屬於模型引導，並非程序級強制控制。

真正的硬邊界來自宿主環境：模型安全政策、文件系統權限、網路權限、工具參數校驗和使用者核准。倉庫不能聲稱僅靠提示詞徹底阻止越權或有害輸出。

## 輸出契約

常規回答應盡量包含：

1. 對使用者情緒和核心矛盾的準確回應。
2. 已知事實、合理推測和關鍵未知的區分。
3. 明確的首選建議及2–4個理由。
4. 必要時提供不同策略強度、話術和預期代價。
5. 一件下一步、觀察窗口或停止條件。

若資訊不足，代理只問1–2個會改變建議的問題；首次建檔也不機械展開完整問卷。

## 失敗處理

- 資料缺失：標註未知，不虛構。
- 資料矛盾：指出矛盾並請求糾正關鍵項。
- 高風險請求：拒絕危險操作部分，提供安全替代。
- 法律或醫療不確定：說明局限，建議核對地區和咨詢合格專業人員。
- 工具不可用：繼續提供純文本支持，不假裝已執行外部操作。
- 記憶寫入失敗：明確說明沒有持久化，不顯示“記憶更新”成功提示。
- ChatLab匯入失敗：保留原文件與現有會話，報告預覽或錯誤提示，不直接編輯資料庫。
