# 長期記憶與關係檔案

## 目標

在使用者首次明確同意後，跨任務復用精簡的使用者、對象和關係資訊。記憶服務於減少重復解釋，不是完整聊天倉庫，也不是對人格的永久判決。

## 首次同意

先運行：

```bash
python3 scripts/memory_store.py status
```

尚未啟用時，用一句話詢問：

> 是否允許狗頭軍師在本機保存精簡關係檔案？同意後會自動更新，每次提示變更，可隨時查看、暫停、撤銷或刪除。

只有使用者明確同意後才能運行：

```bash
python3 scripts/memory_store.py enable --confirm
```

拒絕後本次任務不再追問。宿主無文件權限、腳本不可用或命令失敗時，只沿用當前任務上下文並說明沒有持久化。

## 五類記憶

| scope | 內容 | 合格來源 |
| --- | --- | --- |
| `user` | 使用者的 MBTI、主觀綜合評分、穩定目標、偏好、邊界和溝通習慣 | 使用者明確陳述 |
| `object` | 對象姓名或稱呼、MBTI、使用者主觀評分及使用者明確提供的穩定事實 | 使用者明確陳述或轉述 |
| `relationship` | 當前階段、雙方共識、現實約束和下一步目標 | 使用者明確陳述或轉述 |
| `event` | 帶時間的關鍵轉折、兌現、邀約、衝突與修復 | 使用者敘述；ChatLab或工具只能到此層 |
| `hypothesis` | 性格、依戀、意圖等可被糾正的暫定解釋 | 使用者觀察或模型推斷，必須帶置信度和證據 |

使用者提供的姓名、暱稱或代號都可直接保存為 `display_label`，召回和回覆優先沿用。為控制記憶體積，整份聊天、截圖和匯出文件繼續留在原文件或ChatLab；長期記憶只保存欄位和不超過200字的關鍵事件摘要。

MBTI和主觀評分在首次建檔時主動詢問；使用者說不知道即可留空。MBTI按使用者明確提供或對對象的轉述保存；主觀評分保存為0–100並註明是使用者評價。只按使用者給出的評分定義解釋；沒有定義時稱為“主觀綜合評分”，不得改稱意願、心動、條件或投入分數。評分變化時更新同一欄位，不累積每次分數；MBTI被使用者糾正時覆蓋舊值。

## 自動更新

同意後，每輪先判斷是否出現會影響未來建議的高價值變化。沒有變化就不寫。把當前狀態寫成 `user`、`object` 或 `relationship` 的欄位更新；把一次性轉折寫成 `event`；把讀心或人格解釋寫成 `hypothesis`。同一對象、同一日期、同一事件欄位視為同一事件的後續更新；欄位使用穩定類型，如 `planned_activity`、`conflict`、`repair`，不要為同一件事另造欄位。

示例：

```bash
python3 scripts/memory_store.py apply --json '{"scope":"relationship","subject_id":"obj-a","field":"stage","value":"雙方已確認進入排他約會","source_type":"user_report","source_ref":"turn:當前任務","occurred_at":"2026-08-02","confidence":"high"}'
```

首次同意後，可把已經明確給出的建檔資訊分欄位寫入：使用者使用 `scope=user`、欄位 `mbti`／`subjective_score`；對象使用 `scope=object`、欄位 `display_label`／`mbti`／`subjective_score`。未知項不寫入。評分只接受使用者本人給出的數字，模型不得代填。

每次成功寫入後，在回答末尾用一行說明：

> 記憶更新：對象A的關係階段更新為“排他約會”。撤銷：告訴我“撤銷剛才的記憶”。

不得顯示資料庫路徑、內部JSON或無關舊檔案。自動更新不等於自動相信：對象人格、愛意、忠誠和未來意圖不得升級為穩定事實。

## 讀取與按需披露

只讀取當前對象需要的壓縮上下文：

```bash
python3 scripts/memory_store.py context --subject-id obj-a --max-chars 4000
```

預設最多載入使用者穩定檔案、當前對象快照、少量假設和最近8個關鍵事件。不要把所有對象或完整歷史注入當前回答，不要把召回到的記憶再次當成新資訊寫回。

## 使用者控制

- 查看：`show`，可加 `--subject-id obj-a`。
- 撤銷最近更新：`undo`；若回答中保留了操作編號，可用 `undo --op-id ...`。
- 暫停／恢復：`pause`、`resume`。
- 忘記對象：先確認準確代號，再運行 `forget-object obj-a --confirm`；這是硬刪除並清除撤銷歷史。
- 撤回同意但保留現有資料：`revoke --confirm`。
- 撤回並刪除：`revoke --delete --confirm`。
- 清空全部：使用者明確確認後運行 `clear --confirm`。

腳本將單條內容限制為200字、總記憶限制為200條、每個對象事件20條、假設5條，並只保留最近20次可撤銷操作。達到上限時先合併或刪除低價值事件，不擴容規避限制。

## 設計來源

- [OpenClaw memory](https://github.com/openclaw/openclaw/blob/main/docs/concepts/memory.md)：吸收核心檔案與可檢索事件分層、明文可審閱和按需召回。
- [claude-mem](https://github.com/thedotmack/claude-mem)：吸收漸進披露、先返回壓縮索引和證據編號，不把全部歷史塞入上下文。
- [Napkin skill](https://github.com/blader/napkin)：吸收持續整理、合併重復、刪除低價值內容和分類封頂。
- [Cyrene-Agent](https://github.com/Playa-0v0/Cyrene-Agent) 與 [ZifaMem](https://github.com/zifacorp/zifamem)：吸收明確事實／模型推斷分離、證據、置信度、衝突和替代狀態。
- [Mem0](https://github.com/mem0ai/mem0) 與 [Letta](https://github.com/letta-ai/letta)：只吸收多層記憶與核心／歸檔思路；本Skill不引入常駐服務、雲端依賴或無界ADD-only累積。
